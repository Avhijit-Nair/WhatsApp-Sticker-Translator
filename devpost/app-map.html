Sticker Translator — App Map

A take-home guide to where things live. A snapshot of commit 45583a7; the code may drift after it.

What it is

A Mac menu-bar app that watches WhatsApp Desktop and puts a dark tooltip beside each Spanish sticker, with a literal English translation and what it really means. It runs entirely on-device using frameworks built into macOS 26. Its main pieces:

  • Control panel + readiness: the toggle, and checks for screen permission, WhatsApp and Apple's model.
  • Pipeline: snapshot WhatsApp, read text, keep Spanish, translate (with a slang glossary), cache.
  • Overlay: floating tooltip panels placed beside each sticker on every snapshot.

One action, end to end: a Spanish sticker gets a tooltip

Reference route (3 stops)

A suggested path through the code. Open the project in your editor and search for each anchor.

  1. The loop: Sources/StickerTranslator/Pipeline/LivePipeline.swift, search func tick.
    Each snapshot: read the blocks, skip non-Spanish text, start translating text seen twice in a row, then hand every visible tooltip to the overlay. "Re-scan, don't track" lives here.
  2. The kernel: explaining the joke: Sources/StickerTranslator/Pipeline/Translator.swift, search func translate and static let instructions; plus Pipeline/slang-glossary.json.
    Glossary notes (and a "playful spelling" hint) go into the prompt for Apple's on-device model; the two-line reply is parsed into LITERAL and MEANING, with one retry if it copied the Spanish.
  3. Where the tooltip appears: Sources/StickerTranslator/Overlay/OverlayController.swift, search static func screenRect and func show.
    Converts Vision's 0–1 box (bottom-left origin) into a screen position, then places the panel to the right of the text, or on the left if there's no room.

A practice to reuse

Test the riskiest assumption first, with real inputs, through a small harness, before building the interface.

The spec flagged on-device explanation quality as the main risk (spec.md > Decisions and Open Issues). Build step 1 was therefore a command-line check (--check <image>, in DevCheck.swift), not the overlay. It showed the model confidently explaining "qué oso" as "How cool!" and "aguas" as "I'm thirsty", which led to the slang-glossary decision before any UI depended on the model. Later, the same harness separated two possible causes when "ola wen dia" got no tooltip: the language filter (3% Spanish), not the model.

On another project: write down the one assumption that would sink it, build the smallest runnable thing that exercises exactly that with real examples, and keep it around as a debugging tool.
